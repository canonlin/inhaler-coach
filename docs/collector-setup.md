# 資料收集器：怎麼用

## 給來錄資料的藥師

**打開網址 → 按「開始錄製」→ 照畫面提示做動作 → 把下載的檔案拖進共用資料夾 → 完成。**

全程約 2 分鐘。不用註冊、不用安裝、不用登入。畫面會一項一項告訴你要做什麼。

---

## 給專案主持人：設定（做一次，約 5 分鐘）

沒有伺服器要架，沒有程式碼要貼。只有兩件事。

### 一、開一個共用資料夾

1. 打開 [Google Drive](https://drive.google.com)，新增一個資料夾（例如「吸入器資料」）
2. 在資料夾上按右鍵 →「**共用**」→「**知道連結的任何人**」→ 權限改成「**編輯者**」
3. 按「**複製連結**」

> 權限要給「編輯者」，藥師才能把檔案拖進去。這個資料夾只放研究資料，不要放其他東西。

### 二、把連結設進網頁

在專案資料夾裡建立一個叫 `.env` 的檔案，內容一行：

```
VITE_DRIVE_FOLDER_URL=你剛剛複製的連結
```

然後：

```bash
bun run build
```

把產生的 `dist/` 資料夾發布到 GitHub Pages。藥師的網址會是：

```
https://<你的帳號>.github.io/inhaler-coach/collect.html
```

> 網址一定要是 **https**（瀏覽器規定：不是 https 就不給用相機）。GitHub Pages 本身就是 https，不用擔心。

## 為什麼不是自動上傳？

自動上傳要有一台伺服器收檔案，而架伺服器、管金鑰、設環境變數這些事，會落在**你**身上——一位藥師，不是工程師。

用「藥師把檔案拖進共用資料夾」換掉這一整套，代價只是每位藥師多做一個拖曳動作。這筆帳很划算：沒有伺服器要維護、沒有金鑰會外洩、沒有第三方服務在資料路徑上。資料從瀏覽器直接進到你們自己的 Drive。

## 收到的資料長什麼樣

每次錄製會產生**兩個檔案**：

**`a3f2c1d8_2026-07-15T...webm`** — 原始影片 + 聲音

**`a3f2c1d8_2026-07-15T...json`** — 動作訊號，**每一幀都標好了當下在做什麼動作**

```json
{
  "metadata": {
    "sessionId": "a3f2c1d8",
    "recordedAt": "2026-07-15T...",
    "videoWidth": 640, "videoHeight": 480,
    "userAgent": "..."
  },
  "signals": {
    "frames": [
      {
        "t": 1234,                 // 毫秒，從錄製開始算
        "label": "shake_gentle",   // ← 當下在做什麼（ground truth）
        "handSeen": true,
        "hand": [[x, y, z], ...],  // 21 個手部關鍵點
        "wrist": [x, y, score],
        "motionHand": 12.3,        // 手部區域的像素變化量
        "motionBg": 0.8            // 同一幀的背景 = 雜訊底線
      }
    ],
    "audio": [
      { "t": 10, "label": "spray_x2", "hi": 2.3e-8, "flat": 0.26 }
    ]
  }
}
```

檔名前面那串（`a3f2c1d8`）是隨機產生的代碼，藥師不用記、也不用自己編號。

## 錄製流程包含什麼

10 個任務，正負樣本各半：

| 正樣本（要偵測到） | 負樣本（不可以誤判） |
|---|---|
| 照平常方式搖 | 拿著，完全不動 |
| 用力快搖 | 移動，但不要搖 |
| 輕輕慢搖 | **放下、再拿起吸入器**（測會不會被誤判成噴藥） |
| 只動手腕，小幅度搖 | 說話（測會不會被誤判成噴藥或吐氣） |
| 對空噴 2 下 | |
| 深深吐氣 | |

負樣本刻意放得跟正樣本一樣多。只餵正樣本的偵測器，會把所有東西都當成搖動——這正是先前踩過的坑。

四種不同的搖法也是刻意的：目前的偵測器對**用力快搖**很準，但**輕搖和只動手腕**幾乎抓不到。不同的人搖法差很多，這件事必須用真實的多人資料來解決，而不是對著一個人反覆調參數。
