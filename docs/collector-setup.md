# 資料收集器：怎麼用

## 給來錄資料的藥師

1. 打開研究負責人給你的網址
2. 按「開始」，畫面會一項一項**動畫示範**要做的動作，看懂了再按「我看懂了」
3. 照著做（10 個動作，每個 8–22 秒，做錯可以重錄）
4. 錄完會自動下載**兩個檔案**
5. 把那兩個檔案拖進負責人給你的雲端資料夾

全程約 5 分鐘。不用註冊、不用安裝、不用登入。

> 請用 **Chrome 或 Edge**（Safari 的錄影支援不完整）。

---

## 給專案主持人

**沒有設定步驟。** 部署好之後，你只要做兩件事：

1. 在雲端硬碟開一個資料夾，共用權限設成「知道連結的任何人 → 編輯者」
2. **把網址和資料夾連結一起私訊給藥師**

網頁本身不需要知道資料夾在哪——那個連結由你直接傳給人就好，少一個設定檔、少一個會壞掉的東西。

### 部署

```bash
VITE_BASE=/inhaler-coach/collector/ bun run build
```

把 `dist/` 的內容放進 `main` 分支的 `collector/` 資料夾（GitHub Pages 從 main 根目錄發布）。

網址：`https://canonlin.github.io/inhaler-coach/collector/collect.html`

> 必須是 **https**（瀏覽器規定：不是 https 就不給用相機）。GitHub Pages 本身就是 https。

## 收到的資料長什麼樣

每次錄製兩個檔案：

**`a3f2c1d8_2026-07-15T....webm`** — 原始影片 + 聲音（1280×720、30fps）

**`a3f2c1d8_2026-07-15T....json`** — 動作訊號，**每一幀都標好了當下在做什麼動作**

```json
{
  "metadata": {
    "sessionId": "a3f2c1d8",
    "recordedAt": "2026-07-15T...",
    "cameraSettings": { "width": 1280, "height": 720, "frameRate": 30 },
    "userAgent": "..."
  },
  "signals": {
    "frames": [
      {
        "t": 1234,                 // 毫秒，從錄製開始算
        "label": "shake_gentle",   // ← 當下在做什麼（ground truth）
        "handSeen": true,
        "roi": true,               // 手部框是否可用（含短暫沿用）
        "hand": [[x, y, z], ...],  // 21 個手部關鍵點
        "wrist": [x, y, score],
        "motionHand": 12.3,        // 手部區域的像素變化量
        "motionBg": 0.8            // 同一幀的背景 = 雜訊底線
      }
    ],
    "audio": [
      { "t": 10, "label": "spray_x2", "hi": 2.3e-8, "flat": 0.26 }
    ]
  }
}
```

檔名前面那串是隨機產生的代碼，藥師不用記、也不用自己編號。

`cameraSettings` 記錄的是**相機實際給了什麼**，不是我們要求什麼——每台筆電不同，如果某一份資料的分析結果跟其他人不一致，要能一眼看出是不是相機規格的關係。

## 錄製流程包含什麼

10 個任務，正負樣本各半：

| 正樣本（要偵測到） | 負樣本（不可以誤判） |
|---|---|
| 照平常方式搖 | 拿著，完全不動 |
| 用力大幅度搖 | 移動，但不要上下搖 |
| 很輕、很慢地搖 | **放下、再拿起吸入器**（測會不會被誤判成噴藥） |
| 像手不方便的長輩那樣搖 | 說話（測會不會被誤判成噴藥或吐氣） |
| 對空噴 2 下 | |
| 深深吐氣 | |

負樣本刻意放得跟正樣本一樣多。只餵正樣本的偵測器會把所有東西都當成搖動——這正是先前踩過的坑。

四種不同的搖法也是刻意的：目前的偵測器對**用力快搖**很準，但**輕搖和只動手腕**幾乎抓不到。不同的人搖法差很多，這件事必須用真實的多人資料解決，而不是對著一個人反覆調參數。
