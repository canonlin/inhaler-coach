# Inhaler Coach Demo Runbook

更新：2026-09-02 · 適用：完整四關現場展示

## 展示目標

讓觀眾看懂一條完整、可信的衛教流程：先看示範，再以攝影機觀察可見動作，逐步完成振搖、吐氣姿勢、壓吸姿勢與漱口動作。系統不宣稱 webcam 能直接證明肺內氣流、藥物釋放或憋氣生理事件。

醫療動作文字以 [DailyMed SYMBICORT Instructions for Use](https://dailymed.nlm.nih.gov/dailymed/drugInfo.cfm?setid=fafa4cf1-99c2-43d5-73ad-51f256de3be0) 為產品特定依據；仿單未涵蓋的教學細節才參考通用 pMDI 教材。

## 展示前檢查

在實際 demo 電腦、Chrome、攝影機與網路上依序執行：

```bash
rtk bun install --frozen-lockfile
rtk bun run preflight
rtk /Users/gloomcheng/.codex/typecheck-singleflight.sh bun run typecheck
rtk bun run test
rtk bun run build
rtk bun run test:e2e
rtk bun run dev
```

只有前六項全部成功，才進入瀏覽器彩排。開啟 `http://localhost:5173/`，允許攝影機；麥克風不是目前四關的過關條件，缺少麥克風時會自動使用純影像模式。

確認下列現場條件：

- demo 瀏覽器沒有其他分頁占用攝影機。
- YouTube、jsDelivr、Google model storage 可連線。
- 吸入器、清水與漱口容器已放在鏡頭外但伸手可及的位置。
- 人臉與上半身光線均勻，避免強烈背光。
- 走完一次正常流程，再故意測一次影片或攝影機錯誤畫面。

## 主流程與講法

1. 開場：說明這是四關衛教練習，不是醫療認證。
2. 振搖：使用前持續搖勻 5 秒；畫面觀察手部或吸入器區域的持續動作。
3. 吐氣：吸入器離開嘴邊，完全吐氣；畫面確認的是吸入器位置，不宣稱直接量到吐氣流量。
4. 壓吸＋憋氣：吸嘴入嘴、吸入器直立穩定，深而慢地吸氣並同步按壓；接著依產品指示憋氣約 10 秒或以舒適為限。倒數是教學引導，不是肺內感測。
5. 漱口：以清水漱口後吐掉，不要吞下。
6. 完成：指出四個已練習項目與「不能取代醫師或藥師判斷」的界線。

## 恢復路徑

| 現象 | 畫面上的處理 | Presenter 備援 |
| --- | --- | --- |
| 影片 12 秒未載入 | 選「重新載入影片」 | 選「先進入 AI 練習」 |
| 攝影機或模型失敗 | 選「重新嘗試」 | 回教學影片，或由衛教師協助確認該關 |
| 某關需要重新開始 | 選「再測一次」 | 重新開啟 `/?stage=N`，其中 N 為 1–4 |
| 流程中斷且無法恢復 | 回到開場重新練習 | 使用 `/?stage=N` 從指定關卡接續 |
| 場地網路失效 | 保留可見錯誤與恢復畫面 | 不宣稱影片或雲端模型已成功；改說明本地 ONNX 與已完成的流程設計 |

## 上台前的停止線

- 展示前 45 分鐘停止新增功能，只接受阻塞性修正。
- 完整冷啟動流程連續通過兩次。
- 第二次彩排必須由另一位團隊成員照本 runbook 操作。
- 若 build、typecheck 或完整瀏覽器流程仍未通過，不使用「完成」或「已驗證」描述；改為明確說明目前可展示的範圍。
